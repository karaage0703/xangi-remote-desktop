# 使い方

[README](../README.md) / [セットアップ・設定](../XANGI_SETUP.md) / [設計](design.md)

## 画面操作

1. xangiの拡張一覧から「xangi-remote-desktop」を開きます。
2. 自動認証を使う場合は初回にブラウザを登録します。コードの確認方法は画面内にあります。
3. 「接続する」で画面を表示します。手入力モードではVNCの認証情報を入力します。
4. 「操作を開始」を押し、画面内をクリックするとマウス・キーボードで操作できます。
5. 「操作を停止」で入力を止め、「切断」で終了します。「xangiホーム」で戻れます。

「画面に合わせる」は表示倍率だけを変え、PCの解像度は変えません。対応ブラウザでは全画面表示を使えます。同時接続は1ブラウザまでで、切断後の再接続は手動です。VNCに直接接続する別クライアントはこの制限に含みません。

登録期限の変更・コードの再表示・全登録失効は[セットアップ](../XANGI_SETUP.md#登録コードの確認)を参照してください。

## 対応状況

| 対象 | 対応・検証状況 |
| --- | --- |
| Linux X11 | Chromiumで画面表示・マウス／キー入力を確認 |
| Linux Wayland | 環境別の実機検証が必要。RDPのみのサーバーには非対応 |
| macOS | POSIXランチャーあり。標準画面共有・Apple固有認証は実機未検証 |
| Windows | ネイティブ起動ランチャー・実機検証は未対応。WSLからWindows画面への接続も未保証 |
| ブラウザ | Chromiumで検証。MacのChromeからLinux X11への英数入力も下記の条件で確認。Safari・Firefoxは未検証 |

自動認証はRFB 3.3/3.7/3.8の標準VNCパスワード認証のみ対応します。手入力でも証明書の手動承認やusername/password以外の入力が必要な方式は非対応です。日本語IME・特殊キーは下記の限定的な確認を除き未検証です。複数画面・OSロック・UAC・ログイン画面は未検証です。

## 困ったとき

- **接続できない**：VNCの待ち受け先・ポート・認証情報、別タブの接続有無を確認します。`doctor`はVNCへの接続成功までは確認しません。
- **登録を保存できない**：Cookieの許可と、設定に合ったHTTPS等の接続先を確認します。
- **入力できない**：「操作を開始」が有効か、画面内にフォーカスがあるか確認します。
- **手入力の認証が動かない**：方式によってWeb Cryptoが必要です。HTTPSまたはlocalhostを使用します。

## MacからLinux X11へのキー入力

以下はMacのChrome → noVNC → x11vnc → Ubuntu 24.04系のX11環境で確認した対処です。macOSを接続先にした検証ではなく、他のOS・VNCサーバーに共通する必須設定でもありません。変更対象は接続先のVNC設定とOSパッケージで、拡張本体のコード更新は不要です。

### Shiftが効かない・英数キーの後に大小文字が逆転する

まず接続元ブラウザのShift・Caps Lockと、接続先のロック状態を分けて確認します。今回の環境では、日本語配列の`Eisu_toggle`がCaps Lockと同じキー位置にあり、Macの英数キー相当の送信で接続先のCaps LockがONになる現象を再現しました。操作の停止・開始やページ再読込だけでは再発を防げませんでした。

この環境で使用したx11vnc側の設定は次のとおりです。

- 環境変数：`MODTWEAK_LOWEST=1`
- 起動引数：`-noxkb -remap Eisu_toggle-Muhenkan`

`MODTWEAK_LOWEST=1`は重複するキー割り当ての選択を補正しますが、これだけでは英数キーによる再発を防げませんでした。`-remap Eisu_toggle-Muhenkan`は英数キーの送信先を無変換キーに置き換え、Caps Lockへの意図しない切替を回避します。英数キーの意味が変わるため、利用するIME・配列で確認してください。`-noxkb`は以前のXKB処理中のクラッシュを避けるために使用していた設定です。クラッシュの根本原因は未確定で、すべての環境に推奨するものではありません。

systemdで起動している場合、環境変数はVNCのサービス定義の`[Service]`に`Environment=MODTWEAK_LOWEST=1`として指定し、既存の`ExecStart`に必要な起動引数を追加します。拡張の`.env`に書いても別サービスのx11vncには反映されません。既存のDISPLAY・Xauthority・loopback待受・認証設定を維持し、変更前のサービス定義を退避してください。

反映にはVNCサービスの再起動が必要で、接続は一度切れます。systemdの定義を編集した場合は先にdaemon-reloadを行います。xangi本体の再起動は不要です。既にONになった接続先のCaps Lockも確認・解除したうえで、再接続後に「英数キー → 小文字 → Shift付き大文字 → 小文字 → Enter」を繰り返して確認します。この連続試験とMacからの操作で改善を確認しましたが、長時間の再発なしを保証するものではありません。

### GTK4アプリで日本語が入力できない

Mozcが動いていても、GTK4との連携部品が不足すると、GTK3では変換できるのにGTK4の編集アプリでは英字のままになる場合があります。今回のUbuntu環境では`ibus-gtk4`が未導入でした。

```sh
dpkg-query -W ibus-gtk4
# 未導入の場合に接続先のUbuntuで実行
sudo apt-get install ibus-gtk4
```

導入後、新しく起動したGNOME Text EditorでnoVNC経由の`ka`が「か」になることを確認しました。既に開いているアプリは、未保存文書を保存してから起動し直す必要がある場合があります。Mac側をABC入力にし、接続先でMozcのひらがな入力を選んで確認します。Mac側で変換済みの日本語を直接送る操作の検証ではありません。

**残る制限**：日本語入力中のEnterによる確定・改行が反応しない、または遅く感じられる症状は未解決です。利用者はマウスでの選択を回避手段として使用しています。`ibus-gtk4`の導入や英数キーの対策だけで、日本語入力全体が解決したとは扱わないでください。

## 制限

「入力停止」は誤操作防止で、閲覧専用の権限ではありません。登録済みブラウザを持つ人はPCを操作できます。xangiへのアクセスを本人・許可した利用者に制限してください。

音声・ファイル転送・クリップボードUI・解像度変更・OSの自動設定・利用者ごとの操作権限・AIへの操作権の引き渡しは含みません。
